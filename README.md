# Рабочее место ППО ВОЛС

Комплект для предпроектного обследования опор ВЛ под размещение сетей электросвязи
и формирования отчёта владельца инфраструктуры по пункту 13 Правил недискриминационного
доступа (ПП РФ от 22.11.2022 № 2106).

Всё работает целиком в браузере. Данные никуда не передаются.

## Главный формат данных

**`ID_shablon.xlsx`** — единственный источник исходных данных. Отчёт всегда собирается
из этой книги, кем бы она ни была заполнена.

Заполнить её можно двумя способами, результат одинаковый:

* **вручную в Excel** — как раньше, по инструкции;
* **через форму «Осмотр»** — она заполняет ячейки ручного ввода за вас.

Форма правит книгу точечно: заливка ячеек, выпадающие списки, именованные диапазоны
и все ~3000 формул шаблона остаются на месте. Материал и тип опоры, состояние по
ГОСТ 31937-2024, лист «Мероприятия» и Блок 1 листа «Нагрузки» по-прежнему считает сам Excel.
Если опор больше, чем строк в шаблоне, строки дописываются вместе с формулами и списками.

Книгу, заполненную вручную, форма читает обратно — кнопка «Загрузить шаблон Excel».

## Сквозной путь: обход в поле → отчёт

1. **Выезды** — сгруппировать объекты по маршрутам, прикинуть поездки и километраж.
2. **Обход** — пройти линию, ставя метки с фотографиями в любом приложении, которое
   сохраняет KMZ (Locus, OsmAnd, Google Earth). Подпись метки — по схеме ниже.
3. **Импорт KMZ** (`potok.html`) — пять шагов: файл → проверка распознанного →
   реквизиты отчёта → перенос → готово.
4. **Измерения** — полевые калькуляторы; каждый результат кнопкой уходит в осмотр.
5. **Отчёт** — «Взять данные из осмотра», затем «Фотографии из осмотра → приложение В».
   Выгрузка: PDF, PDF с водяным знаком, Word.

Шаги 2 и 3 можно заменить ручным вводом в разделе «Осмотр» или заполнением
`ID_shablon.xlsx` в Excel — результат один и тот же файл.

## Подпись метки в поле

    номер : марка : линия : примечание

| Пример | Что понимает импорт |
|---|---|
| `104:П10-1:ВЛ 10 - Сщ-7` | опора 104, марка П10-1, линия ВЛ 10 Сщ-7 |
| `103: УА10-1` | линия наследуется от предыдущей метки |
| `2-5:П3:ВЛ 0,4 №1 ТП Сщ-7 - 4:Отклонение от оси` | примечание даёт категорию дефекта Б |
| `15П10-1:ВЛ 10 - Сщ-4` | пропущенное двоеточие между номером и маркой |
| `Б/С` | первая часть не номер — в опоры не попадает, показывается отдельно |

Что делается автоматически:

* **Линия** указывается только там, где меняется; остальные опоры её наследуют.
* **Класс напряжения** берётся из названия линии (`ВЛ 10` → 10 кВ, `ВЛ 0,4` → 0,4 кВ),
  при отсутствии — из числовой части марки.
* **Полевые сокращения марок** (П3, УА10-1, П10/0,38, АО3, К3) приводятся к маркам
  справочника по типу опоры и классу. Соответствие показывается на шаге 2 — по одной
  строке на уникальное сокращение, а не на каждую опору. Исходное обозначение
  сохраняется в примечании к опоре: «по данным осмотра — П3».
* **Совмещённые опоры** ВЛ 10/0,4 кВ отмечаются в примечании.
* **Пролёты** считаются по координатам соседних опор внутри линии, в порядке обхода.
* **Категория дефекта** распознаётся по ключевым словам примечания: разрушение, оголение
  арматуры → A; отклонение, наклон, трещины → Б; сколы, загрязнение → В.
* **Даты работ** берутся из отметок времени меток.
* **Фотографии** извлекаются из архива, сжимаются до 1600 px и привязываются к опорам.
  Снимки опор с дефектами попадают в приложение В отчёта автоматически, с подписью вида
  «опора № 102, ВЛ 10 - Сщ-7 — дефект категории Б, ограниченно работоспособное состояние».
  Остальные добавляются кнопкой «Все фото из осмотра».

На шаге 2 можно снять лишние линии, поправить любое соответствие марок и увидеть метки,
не ставшие опорами. Ничего не переносится, пока вы не нажмёте «Перенести».

## Автоматический вывод по измерениям

В форме вводится только замеренное число. Норматив подставляется по классу напряжения,
характеру местности, удельному сопротивлению грунта или типовому проекту, вывод
«соответствует / не соответствует» считается сам. Охвачены все 13 видов измерений
справочника: отклонение стойки от вертикали, прочность бетона, габариты провода и ОК
до земли, расстояния ОКСН до провода и элементов опоры, глубина заложения, диаметр стойки,
раскрытие трещин, защитный слой, сопротивление заземления, расстояния между точками крепления.

Несоответствия автоматически попадают на лист «Мероприятия».

Опоры выбираются группой: галочками, целой линией, диапазоном номеров или по наличию
дефекта. Одно замеренное значение записывается отдельной строкой на каждую выбранную
опору — это обычный случай, когда результат одинаков для всей линии или для группы
однотипных опор. Работает и в полевых калькуляторах, и в форме осмотра.

## Измерительные инструменты

| Инструмент | Что делает |
|---|---|
| Отклонение стойки от вертикали | Датчик наклона устройства или угол, снятый угломером; отклонение в миллиметрах и вид 1/N считаются сами |
| Пролёт между опорами | Координаты опор; вручную не вводится (задаётся только пара соседних опор) |
| Протяжённость участка | Сумма пролётов по координатам; вручную не вводится |
| Высота опоры и точки подвеса | По углу визирования и расстоянию; подставляется в кренометр |
| Габарит до земли | Прямой замер или расчёт через стрелу провеса `f ≈ qL²/8H` |
| Прочность бетона | Серия отсчётов, отбраковка отклонений свыше 10 % по ГОСТ 22690-2015, коэффициент вариации |
| Ширина раскрытия трещин | Экранный эталон с калибровкой по банковской карте (85,6 мм) |
| Сопротивление заземления | Норматив по удельному сопротивлению грунта (ПУЭ-7 гл. 2.5) |
| Пролёты по координатам | Расстояние между точками; заполнение пролётов всей линии разом |
| Компоновка ОКСН | Пять нормируемых расстояний за один заход, запись пачкой |
| Запас несущей способности | Прикидка изгибающего момента до и после подвески ОК |
| Ёмкость опоры | Сколько кабелей ещё поместится с шагом 0,30 м |

Датчики устройства дают ориентировочную точность. Для отчёта используется поверенный
прибор; калькуляторы служат для проверки и пересчёта.

## Границы отчёта

Раздел 1.5 отчёта разграничивает предмет работ.

**В отчёт входят:** визуальный осмотр опор с категорией состояния по ГОСТ 31937-2024;
инструментальные измерения; учёт ранее размещённых элементов сетей связи; сводная оценка
технологической возможности.

**В проектную документацию пользователя** (в отчёте — рекомендательно): поверочные расчёты
нагрузок по ПУЭ-7 и СП 20.13330.2016; выбор марок кабеля, узлов крепления и арматуры;
точки и высоты подвеса, стрелы провеса, тяжения; технические решения по устранению
дефектов; мероприятия по пп. 3–5 ТТ № 282р. Основание — пункты 5.1 и 6 ТТ № 282р.

## Как данные проходят через шаблон

Формулы Excel вычисляет сам Excel — только при открытии файла. Разбор книги в браузере
видит в таких ячейках пустоту. Поэтому производные столбцы восстанавливаются дважды,
независимо друг от друга:

* при выгрузке в отчёт форма подставляет их из справочников сама;
* генератор отчёта дополнительно достраивает недостающее (`backfill`) — материал и тип опоры,
  дефект, состояние по ГОСТ, технологическую возможность, мероприятие, характеристики кабелей,
  Блок 1 листа «Нагрузки» и лист «Мероприятия».

Благодаря этому отчёт получается одинаковым независимо от того, откуда пришли данные:
из формы осмотра, из скачанного шаблона, загруженного обратно, или из книги, в которой
формулы кто-то стёр вручную.

Сквозная сверка «модель → шаблон → обратно» проверяет поля по всем листам и справочникам;
расхождений быть не должно.

Справочник опор в книге Excel и в веб-форме — один и тот же: при сборке шаблона он
выгружается из `ppo-core.js`, поэтому разойтись они не могут.

## Внутренний аудит

При формировании отчёта выполняются автоматические проверки в шести группах
(комплектность, непротиворечивость, метрология, сроки, несущая способность,
разделение ответственности): 60 на пустой форме и до 80 на заполненном отчёте —
часть проверок включается только при наличии соответствующих данных. Результат —
на панели и в «Листе внутреннего контроля качества».

**Несоответствия блокируют выпуск.** Раньше отчёт лишь помечался как не подлежащий
выпуску, а кнопки печати и выгрузки работали независимо от результата контроля —
и оба разобранных отчёта ушли адресатам с несоответствиями. Теперь при попытке
выгрузить или напечатать отчёт с несоответствиями открывается окно с их перечнем,
в котором кнопки выпуска нет. Выпустить документ всё же можно, но единственным
путём: ввести обоснование (не короче 40 символов) и фамилию принявшего решение.
Тогда решение печатается отдельной таблицей в листе внутреннего контроля и уходит
в .docx вместе с отчётом. Молчаливый выпуск невозможен: либо несоответствий нет,
либо в документе стоит подпись под решением их проигнорировать.

Блокирующие проверки, введённые по результатам разбора выпущенных отчётов:

| Группа | Что ловится |
|---|---|
| Непротиворечивость | сумма по технологической возможности ≠ числу опор; аварийные опоры сложены с ограниченно работоспособными; счётчик категорий ≠ ведомости; число мероприятий ≠ строкам приложения Е |
| Непротиворечивость | дефект «отклонение» при выводе «соответствует» в протоколе по той же опоре |
| Непротиворечивость | высота подвеса меньше нормируемого габарита ОК до земли |
| Метрология | одна опора × один вид измерения записаны дважды с разными значениями |
| Метрология | одно значение растиражировано на пять и более опор |
| Метрология | строки протокола без привязки к опоре |
| Метрология | заявленный метод (НК прочности бетона) не подтверждён ни одним протоколом |
| Метрология | категория состояния присвоена по коррозии арматуры без инструментального контроля |
| Несущая способность | в расчёте нет собственных проводов ВЛ; тип ранее размещённых кабелей «не определён» |
| Разделение ответственности | мероприятие группы Е.2 возложено на пользователя инфраструктуры |

## Приложение Ж — методика

Три положения, отличающие текущую версию:

* **Допустимый момент задан по стойке**, а не по назначению опоры: одна стойка не может
  иметь разные допустимые моменты. Подкосы, вторая стойка и оттяжки в запас не учитываются.
* **Расчётный пролёт — наибольший** в пределах марки, а не средний. Для опор в ограниченно
  работоспособном состоянии дополнительно считается вариант с коэффициентом 0,8 к M_доп.
* **Количественный запас выдаётся только для промежуточных опор.** По анкерным, угловым,
  концевым и ответвительным оценка не приводится: они работают совместно с подкосами и
  оттяжками, которых упрощённая схема не описывает. Поверочный расчёт переносится в
  приложение Е.1.

Нагрузки учитываются раздельно по классам напряжения: провода 10 кВ не нагружают опоры 0,4 кВ.

Три ошибки найдены при сквозном прогоне демонстрационного объекта — от файла
обхода KMZ до выпущенного отчёта. Две из них искажали содержание отчётов.

`normCat()` в `ppo-core.js` заменял кириллическую «В» на «Б». Комментарий при

Теперь «В» остаётся «В». Латинская «B», которую не отличить от кириллической на
глаз, приводится к «В» — так же, как латинская «A» уже приводилась к одному виду.

чтении, поэтому пересборка даёт верный результат.

`fixMeasLines()` при каждой загрузке объекта ставил измерению линию первой
опоры с тем же номером. Каждая линия нумеруется с 1, поэтому измерения опор

## Изменения версии 3.6.2

### «Выезды»: объекты с выполненным выездом исключаются по статусу

В реестре договоров появилась графа «Статус» (столбец AA). Объекты со статусом
**«Завершен»**, **«Расторжение»** или **«Согласование»** в выезды больше не
планируются: выезд на них уже выполнен.

Как распознаётся статус:

* графа ищется **по заголовку** «Статус», а не по букве столбца — столбцы в
  реестре переставляют. Если заголовка нет, берётся столбец AA;
* заголовок сверяется **точно**: в реестре есть и другие графы со словом
  «статус» — например, статус оплаты, — и спутать их нельзя;
* значение сверяется **по началу слова**, без учёта регистра и буквы «ё»:
  «Завершён», «завершено», «Расторжение договора», «На согласовании» тоже
  исключаются;
* **отрицание не исключается**: «Не согласовано» начинается с «не» и под
  правило не подпадает.

Исключённые объекты не пропадают бесследно. Под списком поездок выводится
сводка «Исключены из выездов — выезд уже выполнен» с числом и разбивкой по
статусам: после обновления реестра объектов к обследованию заметно меньше, и
видно должно быть, почему. Список ПЭС в фильтре тоже строится только по тем
подразделениям, где есть что планировать.

Прежние правила действуют как раньше: графа «Исключено из выездов» со значением
«да» и заполненная графа «Э3 факт» по-прежнему исключают объект.

В набор проверок добавлен `tools/test-vyezdy.js` — 21 проверка раздела на
модельном реестре: все три статуса, «ё», «На согласовании», отрицание, пустой
статус, статус оплаты, отсутствие заголовка, переставленные столбцы и прежние
правила исключения.

## Изменения версии 3.6.1

### Типовые приборы возвращены вторым уровнем

Перечень средств измерений разделён на два уровня.

**Первый — приборы подразделения.** Склерометр ИПС-МГ4.01 и теодолит РГК Т-05:
по ним известны заводской номер и запись о поверке, поэтому при выборе они
подставляются целиком и реквизиты не расходятся между отчётами. В списке
отмечены звёздочкой.

**Второй — типовые приборы без привязки к экземпляру**, четырнадцать позиций:
измерители прочности и защитного слоя бетона, тахеометр, нивелир, рулетки,
дальномеры, высотомер, измерители сопротивления заземления, трещиномер,
штангенциркуль, цифровой уровень. Они нужны группам осмотра и измерений в ПЭС,
где парк свой: наименование и марка берутся отсюда, заводской номер и запись о
поверке заполняются по конкретному прибору. В отчёт такая позиция без реквизитов
поверки не пройдёт — лист внутреннего контроля её остановит.

Все семнадцать позиций распознаются проверкой применимости средства измерения,
и вместе они покрывают все тринадцать видов измерений.

Угломер RGK U-66 остался среди приборов подразделения, но без признака
«закреплён»: реквизиты поверки по нему пока не внесены, а признак означает
именно их подстановку. Появятся в книге — появится и признак.

В строке-примере листа «СИ» окончание поверки стояло раньше самой поверки.

### Сборщик книги стал безопасен для повторного запуска

Справочники правятся в книге регулярно, и сборщик `tools/build-template.py`
запускается при каждой правке. Три вещи, которые этому мешали:

* **листы задваивались.** «Спр_Провода» и «Спр_Приборы» добавлялись при каждом
  запуске, и книга обрастала копиями. Теперь добавляются только если их нет;
* **диапазоны выпадающих списков не росли вместе со справочниками.** Список

* **правка не находила формулы после Excel.** Открытая и сохранённая в Excel

  по обеим формам записи, а потерянные проверки восстанавливаются.

Проверено: семь наборов примечаний, двадцать четыре проверки ввода и связанный
список марок опор переживают сборку.

Добавлена графа «То же для деревянной стойки». Типовое описание категории A

## Изменения версии 3.5.10

### Переименование опоры на карте снова доходит до «Осмотра»

Ошибка появилась в 3.5.7 вместе с правкой характеристик опоры прямо в карточке
метки. Порядок действий при сохранении получился такой:

1. карточка записывает новый номер в метку;
2. следом записывает характеристики опоры — линию, класс, марку;
3. **каждая такая запись сообщает разделам, что объект изменён**;
4. карта, услышав это, подтягивает данные из «Осмотра» и возвращает метке
   номер опоры — прежний, потому что перенос ещё не выполнялся;
5. перенос уходит уже со старым номером.

Обратная подстановка из «Осмотра» сама по себе нужна: она переносит на карту
переименование, сделанное в карточке опоры. Поэтому она не убрана, а
приостанавливается на время сохранения карточки метки и включается снова после
переноса. Приостановка сделана счётчиком, а не флагом — сохранений может идти
несколько подряд, — и снимается по времени, чтобы неудачный перенос не смог
оставить подтягивание выключенным.

Разбор названия не менялся: «Опора 95» по-прежнему даёт № 95, «оп. № 97а» —
№ 97а, «92/1а» — № 92/1а, а явно заданный «Номер опоры» главнее разбора.
Случаи закреплены отдельными проверками, включая правку названия одновременно
с правкой линии.

## Изменения версии 3.5.9

### Выбор соседа на карте больше не подвешивает браузер

Каждое назначение соседа перерисовывало карту целиком: снимались и заново
создавались все метки, все иконки и все постоянные подписи, а перед этим у всех

|---|---|---|
| пересоздано меток | 1800 | 0 |

Что изменено:

* **перекрашиваются только изменившиеся метки** — прежние признаки цепи

* карточка исходной метки открывается следующим кадром, чтобы её построение не
  складывалось с назначением в одном обработчике.

### Цепь пролётов считается один раз, а не шесть

За одно действие на карте цепь строилась пять-шесть раз подряд: карточкой
метки, обоими полями соседей и перекраской. Данные между этими вызовами не
меняются, поэтому результат теперь держится до ближайшей записи объекта —
ревизию поднимает сохранение. Десять запросов цепи на 600 опорах укладываются в
10 мс вместо 113.

Заодно карточка метки читает объект **один раз** и передаёт снимок всем полям,
а не перечитывает его для каждого.

Поиск начала хода перебирал все пары точек — квадратичный рост, заметный уже на
паре сотен опор. Заменён двухпроходным приближением: самая дальняя точка от
произвольной, затем самая дальняя от неё. Для вытянутой трассы это те же концы;
порядок опор в ходе не изменился, что проверяется отдельно, в том числе на
линии с ответвлением.

Итог: расчётная часть одного назначения соседа — **71 мс вместо 151** на 600
опорах, пересчёт пролётов — 39 мс.

### Новая раскраска меток

Жёлтый цвет занят разрывом цепи — так же, как в разделе «Осмотр», где карточка

| красный | дефект |

В левой панели выведена легенда, чтобы раскраска читалась без инструкции.

## Изменения версии 3.5.5

### Карточка опоры подсвечивается при разрыве цепи

Опора, у которой не определён сосед, выпадает из расчёта: без следующей нет
пролёта, без предыдущей расчётный (ветровой) пролёт считается по половине
единственного звена. Раньше это обнаруживалось только при сборке отчёта.

Теперь такая карточка в списке опор выделяется жёлтым, несёт метку с причиной
и подсказку при наведении. Подсвечивается, когда:

* не определена следующая опора;
* не определена предыдущая опора;
* не определены ни та, ни другая;
* опора отмечена концом участка, а предыдущая не определена.

У конечной (концевой) опоры следующей нет по определению — с неё спрашивается
только предыдущая. Проверяется результат, а не заполненность полей: сосед может
быть найден по координатам, и тогда указывать вручную нечего. Дефектная опора
сохраняет красное оформление, а неполнота привязки показывается меткой.

Заодно пролёты и протяжённость пересчитываются при открытии раздела «Осмотр»:
это производные от координат величины, и список опор не должен показывать
значения, оставшиеся от прежнего состава.

### Повторная выгрузка проверяла устаревший снимок данных

Отчёт строится по снимку данных осмотра, а не по самим данным. Пока снимок не
обновлён, лист внутреннего контроля показывает несоответствия, устранённые в
«Осмотре», — именно поэтому повторная выгрузка в Word выдавала прежние
замечания.

Теперь страница отчёта запоминает отметку времени объекта, по которому собрана,
и сверяется с текущей: при возврате на вкладку, при сохранении объекта и при
изменении хранилища в соседней вкладке. Если данные разошлись, над кнопками
появляется полоса «Отчёт собран по прежним данным осмотра» с кнопкой
пересборки, а выгрузка и печать пересобирают отчёт **до** контроля, а не после.
Отчёт, загруженный файлом с диска, не сверяется: сравнивать не с чем.

### Проверка комплекта в браузерном окружении

Синтаксической проверки недостаточно: она не замечает, что целый блок разметки
не попал в файл. Комплект переведён на прогон страниц в браузерном окружении —

## Изменения версии 3.5.3

### Соседние опоры можно указать вручную

Геометрический ход строится в пределах линии, поэтому опора, продолжение
которой лежит на другой линии или в другом классе напряжения, оставалась без
пролёта: появлялось замечание «Не указан пролёт до следующей опоры», и опора
уходила в расчёт как конец участка.

В карточке опоры появились поля **«Предыдущая опора»** и **«Следующая опора»**.
По умолчанию стоит «по координатам» — рядом показан сосед, найденный
автоматически. В списке для выбора — все опоры объекта, включая другие линии и
классы напряжения, с указанием линии, класса и наличия координат.

Вручную задаётся только сама пара опор — пролёт по-прежнему считается по
координатам обеих. Указанное звено входит в протяжённость участка, участвует в
расчётном (ветровом) пролёте приложения Ж и не задваивается с ходом по линии.
Внутри приложения связь хранится идентификатором опоры (номера повторяются, и
только идентификатор однозначен), а в книге — текстовой ссылкой «линия|номер» в
служебной графе листа «Опоры», по которой она восстанавливается после круга
через шаблон.

Замечание о неопределённом пролёте переписано: оно теперь называет оба выхода —
указать следующую опору или отметить конец участка.

### Признак конца участка больше не выводится из марки

Подсказка «выбранная марка концевая по конструкции — отметьте признак» убрана.
Концевая по конструкции опора сплошь и рядом стоит в середине хода — там, где
линия продолжается на другой фидер или в другой класс напряжения. Такую опору
нужно связать со следующей, а не обрывать на ней расчёт. Признак ставится
только вручную и ни при каких условиях не выставляется сам.

### Протяжённость участка подставляется расчётом

Поле «Протяжённость участка, км» стало расчётным и вручную не вводится. Оно
пересчитывается при открытии объекта и при каждом пересчёте пролётов: сумма
пролётов по координатам, включая звенья ручной привязки. Отчёт тоже берёт
расчётную величину, а записанную в паспорте — только если считать не из чего.

Раньше в одном документе жили три разных числа об одном участке: 0,363 км в
паспорте, 0,417 км суммой приложения Б и 0,278 км по координатам.

### Аудит больше не требует НК прочности по описанию без категории

Проверка «контроль прочности на опорах с коррозией арматуры» и проверка
«дефект подтверждён измерением соответствующего вида» читают графу «Дефект».
Эта графа теперь заполняется только при выбранной категории, поэтому описание,
сделанное без категории, обязательного измерения за собой не тянет: опора не
дефектная, обосновывать нечего. Само описание сохраняется в графе «Примечание».

## Изменения версии 3.5.2

### Правка наименования опоры на карте не доходила до «Осмотра»

Причина — в разборе наименования. `PPOKMZ.parseLabel` рассчитан на полевой
формат подписи «номер:тип:линия» и на всём остальном возвращает пустой номер:
«Опора 93», «оп. № 95», «Опора № 100а» он не понимал вовсе. Номер метки
оставался прежним, и переименование до раздела «Осмотр» не доходило — при том,
что координаты и признаки уходили нормально.

Добавлен мягкий разбор `PPO.poleNumFromName`: сначала полевой формат, затем
отбрасывание служебных слов («опора», «оп.», «стойка», «точка», «№»), затем
первый фрагмент, начинающийся с цифры. Одиночная буква через пробел («12 б»)
приклеивается к номеру, целое слово («45 ввод») — нет. Если цифр нет вовсе,
номером служит само наименование. В карточке метки появилась живая подсказка,
под каким номером опора появится в «Осмотре».

### Описание дефекта больше не делает опору дефектной

Описание — это наблюдение исполнителя, а дефектной опору делает только
категория. Поэтому:

* описание при категории «без дефектов» **не является замечанием** и ничего не
  блокирует;
* такая опора не попадает ни в ведомость дефектов, ни в счётчики состояний, ни
  в мероприятия;
* графа «Дефект» приложения Б у неё пуста, а описание уходит в графу
  «Примечание» — не теряется и не выдаёт себя за дефект.

Прежние ограничения версии 3.5.1 (очистка описания при снятии категории и
запрет сохранить описание без категории) сняты.

### Пролёты считаются исключительно по координатам

Ручной ввод пролёта отменён: поле в карточке опоры стало справочным. На
разобранном объекте ручные пролёты были завышены на 28 % по объекту и до 43 м
на отдельной опоре, а на них строится расчётный (ветровой) пролёт приложения Ж.
Унаследованная метка «введён вручную» снимается при открытии объекта, пролёты
пересчитываются. После сохранения карточки опоры пересчёт идёт сразу — форма и
отчёт больше не расходятся до нажатия кнопки.

### Порядок опор в линии строится по геометрии хода, а не по номеру

Прежний порядок по номеру ломался дважды: обозначения вида «1-11а» и «92/1а»
сортируются не так, как идёт линия, а одноимённые опоры — что в натуре
встречается — вставали в произвольном месте хода. На разобранном объекте из-за
этого появился пролёт 10 м там, где по координатам 53 м.

Опора опознаётся координатами, поэтому и ход теперь строится по координатам:
от края линии (конца наиболее удалённой пары точек) жадным переходом к
ближайшей непройденной опоре, с разворотом в сторону возрастания номеров.
Опоры без координат в геометрический ход не встают и достраиваются по номеру
после него. Одинаковые номера опор замечанием больше не считаются.

Один и тот же ход используется в расчёте пролётов, в приложении Б и в
приложении Ж — смежные опоры везде совпадают.

### Линия измерения выводится от опоры

Измерение выполняется на конкретной опоре; линия у него не самостоятельная
величина, а свойство этой опоры. Пока её вводили руками, в поле попадал
комментарий («ВЛ-10 ТМ-6 наклон опоры»), и строка протокола отрывалась от
объекта. Линия подставляется от опоры при открытии объекта.

### Ранее размещённые ОК вошли в исходные данные приложения Ж

На опорах уже висят кабели связи сторонних операторов — их число заносится при
осмотре в графу «Существующих подвесов связи». В блок 2 «Нагрузок» они не
попадали, и приложение Ж считало момент только по проводам ВЛ: на разобранном
объекте у 13 опор из 15 было по 2—3 подвеса, ни один из которых в расчёт не
вошёл.

Теперь по каждому классу напряжения выводится позиция подвески: количество —
наибольшее число подвесов на опоре этого класса, характеристики — из
справочника кабелей по типовому самонесущему ОК (ОКСН-8-4,0), высота — по
данным осмотра, а при их отсутствии по нормируемому габариту ОК. Происхождение
цифр подписано в примечании строки: марка фактически подвешенных кабелей при
осмотре не устанавливалась, оценка даётся в запас.

### Свои записи справочника не доходили до других разделов

Модуль пользовательских справочников молча ничего не делал, если рядом
оказывался старый `ppo-core.js` — типичный случай после обновления сайта, когда
браузер отдаёт часть файлов из кеша. Запись добавлялась, а в выпадающих списках
не появлялась.

Исправлено с трёх сторон: у модуля появился запасной путь, дописывающий записи
в справочники напрямую; на странице «Справочники» выводится самопроверка —
сколько записей заведено, сколько применено и какая версия ядра загружена; ко
всем подключаемым файлам добавлена версия в адресе, чтобы браузер не отдавал
устаревший файл из кеша.

## Изменения версии 3.5.1

Исправления по результатам разбора отчёта ДРНУ-ППО/2026-23002603007774.

### Ведомость дефектов включала опоры без дефектов

Строки ведомости отбирались по условию «есть описание ИЛИ есть категория».
Из-за этого в отчёт попадали опоры, у которых категория снята, а описание
осталось от прежней правки: они печатались с категорией «—» и состоянием
«Работоспособное» — дефект без дефекта. В разобранном отчёте так добавились
три опоры (93, 96, 97): ведомость показала 7 позиций при 3 категории A и
1 категории Б. Отбор теперь идёт **только по категории**: именно она
определяет состояние конструкции, технологическую возможность и мероприятие.

Устранена и причина расхождения. Категория дефекта правилась с двух экранов —
из карточки опоры и из карточки дефекта, — а описание только со второго.
Снятие категории в карточке опоры оставляло описание висеть невидимым: в форме
его не видно, но в книгу и отчёт оно уходило. Теперь снятие категории очищает
описание, исполнителя, срок и стоимость, а карточка дефекта не даёт сохранить
описание без категории.

### Подвеска класса 0,4 кВ выпадала из расчёта несущей способности

Перечень классов напряжения разбирался по шаблону `[;,]`. В обозначении «0,4»
запятая десятичная: строка распадалась на «0» и «4», и все провода и кабели
класса 0,4 кВ отсеивались от опор 0,4 кВ. Приложение Ж показывало по ним
нулевую нагрузку и запас 100 %. В разобранном отчёте по опоре П8-1 вместо
3,87 кН·м и запаса 80,6 % стояли нули. Класс «10» запятой не содержит, поэтому
дефект проявлялся только на низком напряжении.

Разделителем перечня теперь служит только «;», а сами классы сравниваются
числами: «0,4», «0.4» и «0,40» считаются одним классом. Та же правка внесена в
определение наибольшего класса объекта — раньше на объекте только 0,4 кВ
наибольшим классом выходило «4» и нормируемые габариты не подставлялись вовсе.

### Коэффициент типа местности не применялся

В поле хранится полная подпись — «A — открытые побережья морей…», — а таблица
коэффициентов индексируется одной буквой. Поиск всегда промахивался и молча
срабатывал откат 0,65 (тип В). Отчёт печатал в разделе 3.3 «тип местности A», а
в приложении Ж — «коэффициент 0,65», занижая ветровую нагрузку на 35 % и
противореча сам себе. Теперь берётся первая буква подписи, а нераспознанный тип
выносится отдельной строкой листа аудита, а не подменяется молча.

### Новые проверки

В листе замечаний раздела «Осмотр» (работают на вводе, до сборки отчёта):

* описание дефекта при снятой категории — блокирующее;
* несколько опор с одним номером в одной линии — блокирующее: цепь пролётов
  строится по номеру, и дубликат ставит опору не на своё место в линии;
* ручной пролёт разошёлся с расстоянием по координатам более чем на 25 % или
  7 м. Проверка намеренно дублирует `ppo-audit.js`: она нужна ещё на вводе и
  работает даже если модуль аудита не подключён;
* измерение записано на линию, которой нет ни у одной опоры — обычно в поле
  линии попал комментарий.

В листе аудита отчёта:

* описание дефекта при снятой категории;
* тип местности распознан и применён в расчёте;
* нулевая нагрузка по марке при заданной подвеске — признак того, что позиции
  подвески не сопоставились с классом напряжения опоры.

### 4. Отклонение стойки от вертикали вводится в градусах

Раньше исполнитель вводил отклонение верха от отвеса в миллиметрах. Но в поле
измеряется **угол** — угломером; миллиметры получались обратным пересчётом
в уме или на бумаге.

Теперь вводятся угол отклонения и высота опоры, а программа считает сама:
отклонение верха `dev = H·tg(α)` и относительную величину `1/N = 1/tg(α)`.
В протокол попадают все три величины: угол, расчётное отклонение в миллиметрах
и вид 1/N. Норматив прежний — не более 1/100 высоты опоры.

Ранее введённые измерения **пересчитываются автоматически** при открытии
объекта: `α = arctg(dev / (H·1000))`. Полевой калькулятор кренометра тоже
переведён на угол — датчик наклона телефона теперь отдаёт величину напрямую,
без промежуточного округления через миллиметры.

### 5. Конечная (концевая) опора: пролёт не считается

В карточке опоры появилась отметка **«Конечная (концевая) опора — пролёт до
следующей не считать»**. При ней поле пролёта гасится, а признак становится
сильнее и геометрии, и ранее введённого вручную значения.

Что меняется в расчётах: цепь линии на такой опоре обрывается — следующая по
номеру опора начинает новый участок и не получает пролёта до предыдущей; звено
не входит в протяжённость участка; расчётный (ветровой) пролёт у концевой
считается как половина единственного смежного; замечание «не указан пролёт до
следующей опоры» по ней не выдаётся. В приложении Б в графе пролёта печатается
«конец участка», а в примечании опоры — пояснение, почему графа пуста: иначе
пустая клетка читается как незаполненные данные.

Если выбранная марка концевая по конструкции, программа подскажет проставить
признак, но сама его не поставит: концевая опора может стоять и в середине
обследуемого участка.

Признак переживает круг «выгрузка в книгу → чтение обратно»: он передаётся
служебной графой листа «Опоры».

### 6. Синхронизация при переименовании опоры на карте

Исправлена ошибка: при изменении наименования метки координаты и признаки
в осмотр уходили, а номер опоры оставался прежним.

Причина была в карточке метки. У неё два поля — «Название» и «Номер опоры», —
а в перенос номер брался только из второго. После импорта KMZ оно уже
заполнено, поэтому правка названия в перенос не попадала вовсе.

Исправлено с двух сторон. Во-первых, при изменении названия номер перечитывается
из него тем же строгим разбором, что и при импорте KMZ; явная правка поля
«Номер опоры» по-прежнему главнее. Во-вторых, метка и опора теперь связаны
идентификатором: ядро ищет цель сначала по нему и только потом по паре
«линия + номер» и по координатам. Переименование больше не зависит от того,
совпали ли координаты. Работает и обратное направление — опору переименовали
в осмотре, метка на карте принимает новый номер.

### 7. Наименование объекта подтягивает все линии проекта

Под полем «Наименование объекта» выводятся отметками все линии, встречающиеся

### 8. Схема производства работ и единоличный осмотр

В список схем добавлено **«без снятия напряжения (в охранной зоне, по
распоряжению)»**.

**Приложение В отчёта.** В шаблоне графы «Дефект» и «Примечание» — формулы
VLOOKUP, а правка книги намеренно сбрасывает их кэш, чтобы Excel пересчитал
значения; браузер формулы не вычисляет, поэтому графы приходили пустыми. Теперь
примечание собирается как «наблюдение осмотрщика + типовое последствие по
категории», в генераторе отчёта стоит подстраховка по справочнику дефектов, а
подписи под фотографиями содержат текст дефекта, а не только его категорию.

**Срок предоставления информации.** Из служебных отметок убрана фраза про
30 рабочих дней. Расчётная предельная дата берётся из нового поля паспорта
«Дата исполнения обязательств по договору (счёту)» (вкладка «Объект», группа
«Запрос»). Проверка внутреннего аудита переформулирована соответственно.

**Пункт 6.1** — второй абзац сокращён до «Распределение обязанностей по
выполнению мероприятий определяется договором.»

**Приложение Ж.2** — устранено задвоение в графе «Сведения»: «Нормативная
толщина стенки гололёда» и «Нормативное ветровое давление».

**Форма обязательства о конфиденциальности** — новая страница
`obyazatelstvo.html` (пункт 15 Правил): предмет обязательства, восемь
обязательств пользователя инфраструктуры, изъятия, срок действия и
ответственность, подписи и отметка владельца о регистрации. Заполняется
реквизитами осмотра одной кнопкой, поля правятся прямо на листе, печатается
в ПДФ. Ссылки — в шапке рабочего места, на портале и в панели генератора отчёта.
