# HANDOFF — как продолжить работу над комплектом

Файл для того, кто садится за комплект с нуля: в новой сессии, на другой машине
или после сброса рабочего окружения. Прочитать целиком до первой правки.

---

## 1. Что это за комплект

«Рабочее место ППО ВОЛС» — статический сайт из связанных страниц, который
проводит исполнителя от полевого обхода воздушной линии до готового отчёта
владельца инфраструктуры по пункту 13 Правил недискриминационного доступа
(ПП РФ от 22.11.2022 № 2106).

Репозиторий: `https://github.com/Anatoliy031/VOLS_ARM_V25.git`, ветка `main`.
Текущая версия — в `ppo-core.js`, переменная `VERSION` (на момент написания
**3.5.12**).

Заказчик — Анатолий, департамент развития нетарифных услуг филиала
«Кубаньэнерго». **Не программист.** Из этого следует, как с ним работать
(раздел 7).

---

## 2. Устройство

Сборки нет. Плоские файлы, vanilla JS, подключение через `<script src>`.
Никаких фреймворков, npm-зависимостей в самом продукте и серверной части.
Данные лежат в `localStorage` браузера, ключ `ppo_vols_object_v2`.

| Файл | Роль |
|---|---|
| `ppo-core.js` | **ядро**: справочники, хранилище объекта, расчёты, нормативные проверки, обмен с книгой. Всё существенное здесь |
| `ppo-refs.js` | пользовательский слой справочников (записи, добавленные вручную) |
| `ppo-kmz.js` | разбор KMZ/KML и полевых подписей меток |
| `ppo-geo.js` | геодезические функции |
| `ppo-xlsx.js` | точечная правка готовой книги без пересохранения |
| `ppo-audit.js` | дополнительный слой проверок листа контроля |
| `portal.html` | начальная страница |
| `potok.html` | пошаговый импорт полевого обхода |
| `karta.html` | карта, метки, обмен с осмотром |
| `osmotr.html` | **основной раздел**: паспорт, линии, опоры, измерения, дефекты, мероприятия, приборы, кабели |
| `pribory.html` | полевые калькуляторы |
| `spravochniki.html` | ведение справочников |
| `index.html` | сборка отчёта, лист внутреннего контроля, выгрузка |
| `vyezdy.html`, `obyazatelstvo.html` | планирование выездов, бланк обязательства |
| `ID_shablon.xlsx` | книга исходных данных: листы данных + справочники + выпадающие списки |
| `tools/` | проверки и обслуживание (раздел 5) |

**Один объект обследования за раз.** Разделы работают с одними данными и видят
правки друг друга.

## 3. Правила, которые нельзя нарушать

Выведены из уже допущенных ошибок. Каждая строка — след разбора.

### Величины, которые считаются и вручную не вводятся

* **Пролёт** — только по координатам опор. Ручной ввод отменён: на разобранном
  объекте ручные пролёты были завышены на 28 % и до 43 м на отдельной опоре, а
  на них строится расчётный ветровой пролёт приложения Ж.
* **Порядок опор в линии** — по геометрии хода (`orderByRoute`), не по номеру.
  Обозначения «1-11а» и «92/1а» сортируются не так, как идёт линия, а
  одноимённые опоры в натуре встречаются.
* **Протяжённость участка** — сумма пролётов, включая звенья ручной привязки.
  Раньше в один отчёт попадали три разных числа об одном участке.
* **Отклонение от вертикали** — в поле измеряется УГОЛ; миллиметры и 1/N
  производные.

### Признаки, которые ставит только человек

* **Конец участка** (`endPole`) — никогда не выводится из марки. Концевая по
  конструкции опора сплошь и рядом стоит в середине хода.
* **Ручная привязка соседей** (`prevId`/`nextId`, текстовые `prevRef`/`nextRef`
  вида `линия|номер` для книги) — нужна там, где продолжение лежит на другой
  линии или в другом классе напряжения.

### Дефект

Дефектной опору делает **категория, и только она**. Описание при снятой
категории — наблюдение исполнителя: в ведомость не идёт, уходит в примечание,
ничего не блокирует и обязательного измерения за собой не тянет.

### Массивы справочников

`POLES`, `CABLES`, `WIRES`, `SI_PRESETS`, `LISTS` мутировать **на месте**
(`push`), никогда не переприсваивать: на них замкнуты `poleByMark`,
`polesByKv`, `cableByMark`, `wireByMark` и все выпадающие списки.

### Сопоставление классов напряжения

Разделитель перечня — только `;`. По запятой не резать: в «0,4» она
десятичная, и строка распадалась на «0» и «4» — вся подвеска класса 0,4 кВ
отсеивалась, приложение Ж показывало нулевую нагрузку и запас 100 %.

### Опора опознаётся идентификатором

Сначала `poleId`, затем пара «линия + номер», затем координаты. Номера
повторяются, однозначен только идентификатор.

### Три пути записи в книгу

Блок 2 «Нагрузок» и графы листа «Опоры» пишутся **тремя** функциями:
`buildWorkbook` (книга значениями), `planFor` (план правок шаблона),
`fillTemplate` (прямое заполнение шаблона). Правка в одной без остальных — уже
дважды приводила к расхождению. Проверять сличением, как в
`tools/test-core.js`.

### Быстродействие карты

Перекраска после правки **не должна пересоздавать метки**: сравнивать прежние
признаки с новыми и менять иконку существующего слоя. На 600 опорах полная
перерисовка — около 6600 операций со слоями на одно нажатие и замирание
браузера на секунды. Цепь пролётов кэшируется по ревизии данных
(`poleChain`), ревизию поднимает `save()`.

### Событие `ppo:saved`

Карта слушает его и подтягивает данные из осмотра. Любая запись объекта в
середине обработчика будит это подтягивание. В сохранении карточки метки
подтягивание приостановлено счётчиком `pullMuted` — иначе обратная подстановка
затирает новый номер опоры ещё до переноса.

## 4. Шаблон `ID_shablon.xlsx`

Правится **по внутренней разметке XML**, а не пересохранением. В книге больше
двадцати проверок ввода (в том числе связанный список марок опор через
`INDIRECT` с таблицей соответствия «класс → имя диапазона» на листе
`Спр_Опоры`), семь листов с примечаниями и своё оформление. Пересохранение
любой библиотекой всё это теряет.

Порядок обновления:

    node tools/dump-refs.js          # справочники ядра → tools/refs.json
    python3 tools/build-template.py  # перестроить листы Спр_*
    node tools/test-template.js      # сквозная проверка

Что важно помнить:

* **заголовки граф листов данных менять нельзя** — `importWorkbook` читает по
  ним (`r['Служебная отметка']` и прочие);
* `planFor` пишет в шаблон по смещениям от найденной строки заголовка — не
  вставлять строки на листах данных;
* именованные диапазоны `Опоры_*` пересчитываются сборщиком; для классов 20,
  150, 220 и 330 кВ своих марок нет, они явно отнесены к ближайшему перечню;
* книга — **снимок** данных. Записи, заведённые в разделе «Справочники»
  рабочего места, в неё не переносятся.

## 5. Проверки

Полный прогон перед любой отправкой:

    sh tools/run-all.sh

Сейчас это **188 проверок**: синтаксис, ядро (78), шаблон (26), страницы (84).

**Синтаксической проверки недостаточно.** Она не замечает, что целый блок
разметки не попал в файл — на этом я уже отчитался о готовой работе, которой в
файле не было. Поэтому страницы поднимаются целиком в браузерном окружении:
открывается карточка, читаются поля, нажимается «Сохранить», результат
сверяется с хранилищем.

`tools/harness.js` — общая обвязка. Заглушка Leaflet считает обращения к слоям;
на этом держится проверка быстродействия карты.

При правке кода **дописывать проверку в тот же прогон**, а не проверять руками.

## 6. Работа с репозиторием

Читать можно без учётных данных:

    git clone --depth 1 https://github.com/Anatoliy031/VOLS_ARM_V25.git

Писать — только с токеном, который даёт владелец на сессию (раздел 8 и
инструкция по выпуску токена в переписке). Порядок:

    git -C <копия> config user.name  "Claude (ППО ВОЛС)"
    git -C <копия> config user.email "claude@local"
    git -C <копия> commit -am "краткое описание правки"
    git -C <копия> push https://x-access-token:$GH_TOKEN@github.com/Anatoliy031/VOLS_ARM_V25.git main

Правила отправки:

* **двоичные файлы только через `git push`.** `ID_shablon.xlsx`, `.docx` —
  веб-интерфейс GitHub перекодирует содержимое, и книга перестаёт открываться.
  В репозитории есть `.gitattributes` с `*.xlsx binary`, но он не спасает от
  перекодировки на стороне загрузчика;
* **поднимать версию** в `ppo-core.js` и версию в адресах скриптов
  (`?v=3.5.12`) во всех `.html` — иначе браузер отдаёт часть файлов из кеша, и
  новый `ppo-refs.js` оказывается рядом со старым ядром. Это уже было: свои
  записи справочника не доходили до выпадающих списков;
* **описывать правку в `README.md`** разделом «Изменения версии X.Y.Z»: что
  было, почему сломалось, что изменено. Заказчик читает именно его;
* токен в истории не оставлять: указывать его в адресе одной командой, не
  прописывать в `git remote`.

## 7. Как работать с заказчиком

* **Язык — русский.** Плотно, по делу, без канцелярита и без англицизмов там,
  где есть русское слово.
* Он **не программист**: объяснять причину ошибки через поведение инструмента,
  а не через устройство кода. Имена функций — только когда без них нельзя.
* **Не спрашивать разрешения на объём** — делать и присылать готовое.
* **Присылать файлы для загрузки в GitHub**: изменённые по отдельности плюс
  архив комплекта целиком.
* **Называть, что осталось нерешённым** и что требует его решения. Он отвечает
  по существу, и его ответы меняют постановку (так «пролёты считаем только по
  координатам» и «одноимённые опоры допустимы» пришли от него).
* **Признавать свои ошибки прямо.** Дважды я отчитывался о работе, которой в
  файлах не было. Он это заметил. Объяснять причину, а не оправдываться.
* Комментарии в коде — по-русски, объясняют **почему**, а не что. Многие
  хранят след конкретного разбора: не удалять при рефакторинге.

## 8. Открытые вопросы на сейчас

1. **Инструкция пользователя (PDF) отстала.** Описывает версию 3.5.5, актуальна
   3.5.12. Сильнее всего устарел раздел 6 «Карта»: удаление опоры с карты,
   признаки цепи и характеристики опоры в карточке метки, новая раскраска
   (жёлтый — разрыв цепи, чёрный — нет фотографий), подписи меток, выбор соседа
   на карте. Плюс раздел 10: кнопка «Пересобрать отчёт по новым данным».
   Исходники инструкции в сессии не сохранились — собирались из шести частей
   HTML + CSS и рендерились WeasyPrint. **Стоит положить их в репозиторий**
   (`doc/`), как это сделано с `tools/`.
2. **Фотоматериалы** в отчёте подтягиваются отдельной кнопкой, и никто не
   предупреждает, когда снимки есть, а приложение В пишет «не прилагаются».
   Обсуждалось: подтягивать автоматически либо выводить предупреждение в листе
   контроля. Решение не принято.
3. **Постоянные подписи меток** на карте тяжелы сами по себе при нескольких
   сотнях опор. Не жаловались, но при росте объектов стоит скрывать их при
   мелком масштабе.
4. **Выгрузка филиальных справочников в книгу** — обсуждалась как возможность:
   сейчас записи, добавленные в разделе «Справочники», в `ID_shablon.xlsx` не
   попадают.

## 9. С чего начать в новой сессии

    git clone --depth 1 https://github.com/Anatoliy031/VOLS_ARM_V25.git
    cd VOLS_ARM_V25
    npm install jsdom xlsx          # только для проверок, в продукт не входит
    sh tools/run-all.sh             # убедиться, что всё зелёное ДО правок
    grep -m1 "var VERSION" ppo-core.js

Затем прочитать в `README.md` последние два-три раздела «Изменения версии» —
там свежий контекст, — и только после этого браться за задачу.
