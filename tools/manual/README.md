# Исходники руководства пользователя

Готовый файл лежит в корне репозитория: `Instrukciya_polzovatelya_PPO_VOLS.pdf`.

## Пересборка

    pip install weasyprint
    python3 tools/manual/build.py

Требуются шрифты DejaVu (в Debian и Ubuntu — пакет `fonts-dejavu`).

## Почему части лежат отдельными файлами

Руководство на сорок страниц правится кусками: изменился раздел «Карта» —
трогается только `p2.html`. При одном большом файле каждая правка выглядела бы
переписыванием всего документа, и понять по истории, что именно изменилось,
было бы нельзя.

| Файл | Содержание |
|---|---|
| `p1.html` | Титул, содержание, назначение, первое знакомство, сквозной порядок работы |
| `p2.html` | Портал, импорт обхода, карта |
| `p3.html` | Осмотр — все девять вкладок |
| `p4.html` | Калькуляторы, справочники, отчёт, выезды, обязательство, книга исходных данных |
| `p5.html` | Расчёты, лист внутреннего контроля, разбор ошибок, справочные таблицы |
| `style.css` | Оформление: колонтитулы, врезки, таблицы, содержание с номерами страниц |
| `build.py` | Склейка частей, разметка якорей, вызов WeasyPrint |

## Что нужно помнить при правке

Номера страниц в содержании считаются самим WeasyPrint через `target-counter`.
Чтобы это работало, заголовок должен начинаться с номера раздела («6.4. Карточка
метки»), а пункт содержания — с того же номера: по нему `build.py` проставляет
якорь и ссылку. Пункт содержания без парного заголовка скрипт назовёт в конце
сборки — строка «ссылок в содержании без якоря».

Версия комплекта указана в трёх местах: титул `p1.html`, колонтитул `style.css`,
врезка «О версии» в конце `p5.html`. При выпуске новой версии правятся все три.
