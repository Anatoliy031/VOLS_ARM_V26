# CLAUDE.md — правила работы в этом репозитории

Этот файл читается при каждом запуске. Он задаёт правила, а подробности
архитектуры лежат в `docs/ARCHITECTURE.md` — открывай его перед первой правкой
кода в новой сессии.

## Что это за проект

Рабочее место ППО ВОЛС: комплект статических страниц для предпроектного
обследования опор ВЛ под размещение волоконно-оптических линий связи и выпуска
отчёта владельца инфраструктуры по пункту 13 Правил недискриминационного
доступа (ПП РФ от 22.11.2022 № 2106).

Заказчик — Анатолий, ПАО «Россети Юг», филиал «Кубаньэнерго», департамент
развития нетарифных услуг. **Не программист.** Отвечать по-русски.

Текущая версия — в `ppo-core.js`, переменная `VERSION`.

## Жёсткие технические рамки

* **Никакой сборки.** Vanilla JS (ES5-совместимый стиль: `var`, `function`, без
  стрелок в `ppo-*.js`), плоские файлы, подключение через `<script src>`.
  Ни npm-зависимостей в рантайме, ни транспиляции, ни бандлера.
* **Вся работа в браузере.** Данные — в `localStorage`, сеть нужна только для
  подложки карты и внешних библиотек с CDN. Сервера нет и не будет.
* **Правки хирургические.** Менять точечно, не переписывать файл целиком, не
  переформатировать соседний код, не переименовывать существующие функции без
  необходимости.
* **Массивы справочников мутировать на месте** (`POLES.push(...)`), никогда не
  переприсваивать: на них замкнуты `polesByKv`, `poleByMark`, `cableByMark`,
  `wireByMark` и выпадающие списки всех страниц.
* **Комментарии — по-русски, по делу.** Объясняют *почему*, а не *что*: код
  этого проекта читает не программист, и почти каждая нетривиальная строка —
  след разобранной ошибки. Не писать комментарии-подписи к очевидному.
* **Версия и кеш.** После правки поднять `VERSION` в `ppo-core.js` и обновить
  `?v=…` в адресах скриптов во **всех** `*.html` (иначе браузер отдаёт часть
  файлов из кеша, и старое ядро оказывается рядом с новым — это уже ломало
  пользовательские справочники). В `README.md` добавить раздел с изменениями.

## Проверка перед сдачей — обязательна

Ни одна правка не сдаётся без прогона. Только синтаксиса недостаточно: один раз
из-за этого в файл не попал целый блок разметки, а я отчитался о готовой работе.

```bash
sh tools/run-all.sh          # синтаксис + ядро + шаблон + страницы в jsdom
```

Что проверяется и почему именно так:

1. **Синтаксис** всех `.js` и всех инлайн-скриптов в `.html`.
2. **Ядро** — расчётные инварианты на узлах, перечисленных ниже.
3. **Шаблон** — сквозной круг «объект → заполнить `ID_shablon.xlsx` → прочитать
   обратно → сверить».
4. **Страницы в браузерном окружении** (`jsdom`, заглушки Leaflet/proj4/XLSX):
   страница поднимается целиком, форма открывается, поля читаются, значения
   сохраняются, результат сверяется с хранилищем. См. `tools/harness.js`.

Добавляя функциональность, **дописывай проверку в `tools/`**. Проверка,
закрепляющая разобранную ошибку, ценнее трёх проверок «на всякий случай».

## Расчётные инварианты — ломать нельзя

* **Пролёт считается только по координатам.** Вручную не вводится. Поле в
  карточке опоры справочное.
* **Порядок опор в линии — по геометрии хода**, не по номеру: обозначения
  «1-11а», «92/1а» сортируются не так, как идёт линия, а одноимённые опоры с
  разными координатами в натуре встречаются и допускаются.
* **Протяжённость участка** — сумма пролётов по координатам, включая звенья
  ручной привязки соседей. Расчётная, ввод закрыт.
* **Признак «конец участка» ставится только вручную.** Никогда не выводится из
  марки: концевая по конструкции опора сплошь и рядом стоит в середине хода.
* **Дефектной опору делает категория, и только она.** Описание при категории
  «—» — наблюдение исполнителя: в ведомость дефектов не идёт, уходит в
  примечание.
* **Опоры, воспринимающие тяжение** (анкерные, угловые, концевые,
  ответвительные), количественного запаса в приложении Ж не получают: «не
  выдаётся». Это граница предпроектного обследования, а не пробел расчёта.
* **Допустимый момент задаётся по стойке**, не по назначению опоры.
* **Классы напряжения сравнивать числами.** Разделитель перечня — только `;`:
  в «0,4» запятая десятичная. Разбиение по `[;,]` однажды выкинуло всю подвеску
  0,4 кВ из расчёта несущей способности.

## Где легко сломать — проверяй отдельно

* **Блок 2 листа «Нагрузки» заполняется тремя путями**: `buildWorkbook`,
  `planFor`, `fillTemplate`. Правка, сделанная в одном, нужна во всех трёх.
  Дважды забывал.
* **`ID_shablon.xlsx` править только по XML** (`tools/build_template.py`): в
  книге 21 проверка ввода, включая связанный список марок через `INDIRECT`,
  семь листов с примечаниями и своё оформление. Пересохранение любой
  библиотекой всё это теряет.
* **Имена графов книги — контракт.** `importWorkbook` читает по заголовку
  (`r['Служебная отметка']`). Менять текст заголовка нельзя.
* **Карта: не перерисовывать все метки.** На объекте в сотни опор полная
  перерисовка со снятием и созданием постоянных подписей подвешивает браузер на
  секунды. Менять иконку существующего слоя через `setIcon` и только у тех
  меток, у которых изменился признак.
* **Обратная подстановка из осмотра.** Правка карточки метки записывает объект
  несколько раз, каждая запись поднимает событие `ppo:saved`, а карта на него
  подтягивает данные из осмотра. Во время сохранения карточки подтягивание
  приостановлено счётчиком `pullMuted` — снимать эту заглушку нельзя, иначе
  переименование опоры на карте перестанет доходить до «Осмотра».
* **Кэш цепи пролётов** (`poleChain`) обесценивается счётчиком `_rev`, который
  поднимает `save()`. Добавляя путь записи в обход `save()`, поднимай `_rev`.

## Тон ответов заказчику

Коротко, по-русски, без канцелярита и без англицизмов там, где есть русское
слово. Сначала — что именно было не так и почему, потом — что сделано, в конце —
что загружать. Измеренные числа вместо оценок «стало быстрее». Если правка
внесена не полностью или проверена не до конца — сказать прямо, а не умолчать.
Ошибку признать без самоуничижения и сразу показать исправление.

## Открытые вопросы

Список ведётся здесь. Закрывая пункт, убирай его.

1. **Инструкция пользователя (`docs/Instrukciya_polzovatelya.pdf`) описывает
   версию 3.5.5.** Не описаны: удаление опоры с карты, признаки цепи и
   характеристики опоры в карточке метки, новая раскраска и подписи меток, поиск
   и выбор соседа, кнопка пересборки отчёта, обновлённый шаблон. Раздел 6
   «Карта» устарел сильнее всего. Собирается `tools/build_manual.py`.
2. **Фотоматериалы в отчёт подтягиваются отдельной кнопкой.** Если снимки в
   объекте есть, а в приложении В написано «не прилагаются» — никто не
   предупреждает. Решить: подтягивать автоматически либо выводить замечание.
3. **Постоянные подписи меток** тяжелы сами по себе при нескольких сотнях опор.
   Обсуждалось скрытие при мелком масштабе — заказчику не предлагалось.
4. **64 марки опор несут отметку «по аналогии»**: момент, высота подвеса и
   габаритный пролёт приняты по стойке-аналогу. Подтвердить по типовым
   проектам. Семь файлов архива — сканы без текстового слоя (`21.0112`,
   `3.407.1-143` вып. 3 и 5, `Б3.507.1-3.04`, `3.320-1.1`), марки оттуда не
   внесены.
5. **Выгрузка филиального справочника в шаблон.** Свои позиции из раздела
   «Справочники» в `ID_shablon.xlsx` не попадают. Предлагалось сделать кнопкой.
